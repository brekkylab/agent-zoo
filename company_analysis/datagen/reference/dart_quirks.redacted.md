# OpenDART 실물 관찰 기록

실제 호출로 받은 응답에서 확인한 내용이다.
**개발가이드 필드표에 없는 것만** 적는다. 필드 목록 자체는 가이드를 보면 된다.

회사명·고유번호·금액 등 특정 기업을 가리키는 값은 형식만 남기고 가상값으로 바꿨다.
관찰 대상은 네 유형이다 — **A**: 대형 제조업 상장사 / **B**: 적자 코스닥 상장사 /
**C**: 금융지주 / **D**: 비상장 법인.

---

## 1. `corp_name`이 엔드포인트마다 다르다

같은 회사인데 값이 다르다. **이름으로 조인하면 안 된다.**

| 회사 | `corpCode.xml` | `company.json` | `list.json` | `company.json`의 `stock_name` |
| --- | --- | --- | --- | --- |
| A | `가나전자` | `가나전자(주)` | `가나전자` | `가나전자` |
| B | `다라` | `주식회사 다라` | — | `다라` |
| C | `마바지주` | `(주)마바금융지주회사` | — | — |

법인격 접미사 표기가 4가지다 — `X(주)` / `주식회사 X` / `(주)X` / 없음.
정규화 규칙을 하나로 못 만든다. `corp_code`로만 조인해야 한다.

## 2. 결측 표현이 엔드포인트마다 다르다

| 위치 | 비상장사의 `stock_code` |
| --- | --- |
| `corpCode.xml` | `' '` — **공백 1자** |
| `company.json` | `''` — 빈 문자열 |

`if stock_code:`로 상장 여부를 판정하면 `corpCode.xml`에서 전부 상장으로 오판한다.
`ir_url`, `hm_url`, `rm`도 결측이 `null`이 아니라 빈 문자열이다.

## 3. `fs_div` 파라미터가 필터로 동작하지 않는다

**가장 위험한 것.** `fs_div=CFS`로 요청해도 응답에 CFS와 OFS가 **둘 다** 온다.

```
A사 2025 사업보고서, fs_div=CFS 요청 → 30행
  CFS(연결재무제표) 15행 + OFS(재무제표) 15행

  매출액 CFS ord=23  123,456,789,000,000
  매출액 OFS ord=24   74,000,000,000,000   ← 40% 차이
```

응답에서 직접 `fs_div`로 걸러야 한다. 안 하면 답이 완전히 틀린다.

## 4. `당기순이익(손실)`이 한 응답에 두 번 나온다

같은 값이 `ord=29`와 `ord=61`에 중복 등장한다(A·B 공통).
`account_nm`으로 group by 하면 이중 계상된다. `ord`는 연속이 아니다(1,3,5,7,…,23,…,61,63).

## 5. 금액은 콤마 낀 STRING, 음수는 `-` 접두

```
'123,456,789,000,000'    A 매출액
'-12,345,678,901'        B 영업이익 (적자)
'-98,765,432,109'        B 이익잉여금
```

괄호 표기가 아니다. 단위는 **원 단위 그대로** — 백만원/천원 환산이 아니다.
따라서 대기업은 15자리, 중소기업은 11자리로 자릿수 폭이 크다.

## 6. `thstrm_dt` 포맷이 `sj_div`마다 다르다

```
BS: '2025.12.31 현재'
IS: '2025.01.01 ~ 2025.12.31'
```

`thstrm_nm`은 `'제 57 기'` — 공백이 들어간 기수 표기.

## 7. 계정 집합이 회사·업종마다 다르다

| 회사 | 행 수 | 특징 |
| --- | --- | --- |
| A | 30 | 표준 제조업 |
| B | 32 | `영업비용` 추가 |
| C | 35 | `매출액`·`영업이익` **없음**. `순이자손익`/`이자수익`/`이자비용`/`순수수료손익`/`예수부채`/`보험계약부채`. 영업이익은 `영업이익(손실)`로 표기 |

제조업 기준 쿼리(`account_nm='매출액'`)를 금융업에 돌리면 0행이다.
`영업이익` vs `영업이익(손실)`도 문자열이 다르다.

## 8. `induty_code` 자릿수가 섞여 있다

| 회사 | 값 | 자릿수 |
| --- | --- | --- |
| A | `264` | 3 |
| 대형 인프라 상장사 | `35120` | 5 |
| 대형 인터넷 상장사 | `63120` | 5 |
| B | `58222` | 5 |

KSIC 3자리(소분류)와 5자리(세세분류)가 혼재한다. 조인 전에 자릿수를 맞춰야 한다.
그리고 B는 주력이 의료 AI인데 `58222`(응용 소프트웨어 개발)다 — **업종코드로 사업을 판단하면 안 된다.**

## 9. `ceo_nm`은 복수 가능, 구분자가 일관되지 않다

```
'홍길동, 김철수'    A — 콤마 + 공백
'이몽룡,성춘향'     D — 콤마만
'강감찬'           B
```

## 10. `corpCode.xml`에 폐지 법인이 남아 있고, 동명이인이 있다

- 전체 118,712건, 30MB. 상장/비상장/폐지 구분 없이 전부 들어 있다.
- **상장폐지된 법인이 `stock_code`를 단 채 남아 있다.**
- **동일 상호가 2건인 경우가 있다** — 비상장(`corp_cls=E`) 법인과 상장 법인이
  같은 이름으로 각각 존재한다. 이름만으로 찍으면 틀린다.
- `modify_date`가 2017년, 2023년 등으로 오래된 레코드가 많다.

## 11. 데이터 없음은 `013`, `list` 키 자체가 없다

```json
{"status":"013","message":"조회된 데이타가 없습니다."}
```

빈 배열이 아니라 **키 부재**다. `d['list']`가 `KeyError`를 낸다.
없는 `corp_code`도, 재무제표가 없는 비상장사도 똑같이 `013`이다 —
"존재하지 않음"과 "데이터가 없음"이 구분되지 않는다.
(메시지의 "데이타"는 원문 그대로다.)

## 12. `list.json`은 노이즈가 지배적이다

A사 8개월치(2026-01-01~08-18): `total_count` **2,747건**. 대부분
`임원ㆍ주요주주특정증권등소유상황보고서`다. `pblntf_ty` 필터 없이 쓰면 못 쓴다.
`report_nm`에 `[기재정정]` 접두가 붙은 정정 공시가 섞여 있고, `ㆍ`(U+318D)가 쓰인다.

## 13. 기타

- `hm_url`에 스킴이 없다 — `'www.example.co.kr/ir'`
- `corp_name_eng`에 오타가 그대로다 — `'GANA ELECTRONICS CO,.LTD'` (콤마·마침표 순서가 뒤집힌 원문)
- `est_dt`는 `'19980401'`(YYYYMMDD 문자열), `acc_mt`는 `'12'`
- `company.json`에 `status`(존속/해산)도 `employees`도 없다. 이 둘은 GLEIF에서 가져와야 한다
- 호출 한도 일 20,000건. 초과 시 `status=020`
